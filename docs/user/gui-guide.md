# GUI 指南

## 概览

显示已管理、未管理、系统 Skills、待处理报告、分组和最近操作。

## Skills

可以搜索、查看来源、版本和本地修改。支持全选当前结果、反选当前结果和清空选择。
表格不显示无必要的 Skill 图标；鼠标悬停或用键盘聚焦任一信息列，会显示该列的
完整内容。允许选择单个或多个个人 Skills 移至隔离区；系统 Skills 不可选。

选择一个或多个“未管理”Skills 后，可以点击“管理”。工具先生成只读
分析计划并执行安全扫描；确认后只写入来源锁和文件哈希，不会移动或改写 Skill
内容。程序按可信目录、`SKILL.md` 显式来源、Git remote 和 GitHub 链接依次识别
来源，确认页会显示分组、依据和置信度。无法确认远程来源的项目分别进入独立本地
分组。管理事务可以从历史页回滚，回滚只恢复来源锁，不移动 Skill。

## 安装 Skill

安装窗口固定为“来源 → 评估 → 复核 → 执行”四步。输入 GitHub 或本地目录后，
应用自动完成必选检查，并用“可继续 / 需关注 / 已阻止 / 检查不完整”给出明确结论。
评估卡片按“必选、按条件触发、可选”分组，直接列出项目类型、说明文件、Codex
Skills、证据、实际写入目标和是否可恢复。普通 Skill 仓库无需理解安装模式；完成
评估后直接选择 Skill 即可。

GitHub 来源绑定完整 Commit；本地来源会先复制到受管快照，后续复核与执行不再读取
正在变化的原目录。未知状态、摘要不一致、不受支持目标和任何大小写形式的 `.system`
都会失败关闭。只有“可继续”或“需关注”状态允许进入执行。

安装窗口把来源、分析结果、权限、执行进度和错误放在同一条流程中。GitHub 403、
无效链接、暂存或扫描失败会直接显示在窗口内，并提供对应的重试提示，不需要先
关闭窗口再查看主页面通知。GitHub 限流会显示恢复时间和倒计时；倒计时结束前不会
重复请求，并可直接打开设置检查凭据。

如果仓库在不同目录提供了内容不同的同名 Skill，窗口会列出冲突路径。识别到
`skills-codex` 镜像时，可以直接选择“使用建议的 Codex 目录”重新分析，不需要
手工拼接链接。

“标准安装”只写入明确选中的 Skills。复杂项目可在复核页明确点击“运行增强项目扫描”
启用 Codex；它会复用同一来源评估，再按“本地结果→文件摘要→重点文件分析”生成
只读项目扫描。敏感凭据类文件只发送元数据，大文本会截断，每次输入都有固定预算。
首阶段只返回项目概述、安全结论、证据限制和声明式安装方式，不下载依赖、不生成
计划。使用者阅读结果并点击“同意并生成安装计划”后，Codex 才会提出安装要求、
结构化步骤和权限清单。分析使用当前设置中的模型与推理强度，会消耗额度。

应用不会把 Codex 文本当作命令运行。自动步骤只允许安装选中的 Skills、从官方
PyPI 安装与仓库匹配的固定版本 Python 工具，以及为该受管工具添加 Codex MCP
配置。受管工具与 MCP 自动集成需要 GitHub 来源以验证包归属。其余步骤只显示
人工说明；应用会先完成已批准的自动步骤，再以“部分完成”列出人工步骤。MCP
配置必须指定一个真实 Git 或 SVN 项目目录，也不会覆盖已有的同名 MCP 配置。

如果计划包含 Python 工具，计划生成阶段会从官方 PyPI 下载完整 Wheel 依赖到隔离
暂存区，并显示固定的文件名与 SHA256。源码包会被拒绝；含本机代码的 Wheel 会
标为高风险并要求单独批准。执行阶段只从这份锁定清单离线安装。

执行前必须明确勾选所需权限。执行中会显示当前步骤、完成数量、分析活动数和错误；
右上角可隐藏窗口，让任务继续在后台运行，重新打开时会恢复有效计划与最新进度。
Codex CLI 返回失败事件时，窗口会显示其中的实际错误；正常模型输出和仓库正文不会
写入诊断。若计划仍无法生成，来源评估、风险结果和 Skill 选择会保留，可切换到
标准安装，仅安装基础 Skills。
应用意外退出会把未完成的分析标为“已中断”，不会把来源计划误当成安装计划。失败
后必须回到审批页，重新核对原 Skill 子集、权限和项目目录，不能直接复用旧授权。
失败或取消时会自动逆序恢复已完成的可逆步骤；恢复不完整时会显示人工路径。“部分
完成”的人工事项和回滚入口也会保留在历史页，并优先展示到恢复完成。若 Codex
不可用或无法生成可靠计划，可保留来源分析和 Skill 选择，直接切换到标准安装。

## 分组

真实来源分组由仓库自动确定，并始终用于安全检查和更新。显示用的管理分组可以
新建、改名和拖动排序；也可以把 Skill 拖到另一个非系统分组。手动整理不会改变
真实来源。每次分组修改都会记录事务和备份，可在历史页回滚。页面使用直接的分组
与 Skill 卡片展示，不绘制容易造成干扰的关系图。

## 更新中心

“检查更新”会为每个来源显示“已是最新、发现新版本、不支持在线更新、已限流或检查
失败”，并保留上次检查时间、远端 Commit、错误原因和具体待更新 Skills。限流时显示
恢复倒计时，临时失败不清除上一次成功状态，并可单独重试。检查结果重启后仍然保留。

发现新版本后，可使用“全选可更新、反选、清空”或逐项勾选来源，再点击“审查所选”。
程序会为每个来源下载不可变 Commit，并且只扫描实际要更新的 Skill 目录，不让仓库
README、工作流、测试或其他未安装内容影响门禁。确认窗口允许继续按来源选择具体
Skills，并展开查看风险位置、命中内容、原因和处理建议。

批量更新按来源建立独立事务：每个来源有自己的备份、日志和回滚入口；个别来源失败
时会明确列出结果。未选中的 Skill 仍会正确显示可更新。实际目标中的 High/Critical
默认阻止写入；High 必须逐簇确认并填写原因，Critical 不可忽略。批量处理不会接受
High 或 Critical。

通过 GitHub 新安装的 Skills 会按仓库自动建立来源分组，无需手动创建分组。

## 安全中心

扫描个人 Skills，不扫描 `.system`。尚未检查或内容已变化的 Skill 默认选中；已检查且
内容未变化的 Skill 默认跳过，也可以手动勾选。队列支持恢复推荐、全选、反选和清空。
结果按“分组 → Skill → 警告”显示，每项包含等级、原因、相关文件和处理建议。分组、Skill
明细和 Codex 结论默认折叠，需要时再展开，避免大量结果占满页面。

安全红点表示“最新有效扫描中尚未处理的唯一 High/Critical 发现数量”，不是历史
报告数量，因此重复扫描同一问题不会累加。Critical 始终阻止且不能忽略；High 必须
逐簇明确确认并填写原因。批量处理不能绕过这两条底线，也不要求先执行 Codex 复核。相同发现
后续再次出现时仍保持决定，恢复后重新参与计数和门禁。应用会按分组打包完整 Skill
上下文交给 Codex，并关闭 Shell 工具；同组 Skills 不会被拆开。复核期间会显示当前分组、
分析活动数和耗时；切换页面后任务与结果仍会保留。失败或漏交结论的分组会自动串行
重试一次；完成后可逐个展开 Skill 摘要和关注项。最终决定始终属于人工。

## 历史与回滚

显示事务 ID、目标、时间和状态。回滚时，当前版本先移动到隔离区，再恢复备份。

## 设置

“语言”支持简体中文和 English。首次运行以及没有语言记录的旧配置默认使用中文；
选择语言后界面立即切换并自动保存，下次启动继续使用。路径、规则名称、日志和用户
自定义的 Skill/分组内容保持原文。

可以修改 Skills、数据、报告、备份、隔离和暂存目录。修改后使用绝对路径并重启程序。
设置页还提供 GitHub 公共/私有仓库凭据验证、API 限额、Codex CLI 复核配置、应用版本、
环境诊断，以及“自动管理已知 Skills”入口。凭据只保存到 Windows 凭据管理器，不写入
日志或报告。Codex 复核默认关闭，可配置 CLI 路径、模型、推理强度和同时复核的分组数；
默认使用 Codex 当前默认先进模型、中等强度，并串行处理分组。同组 Skills 始终一起复核；
提高并发可能造成 CLI 模型刷新竞争或限流。
这里的启用开关只控制安全中心风险复核。“安装 Skill”窗口主动点击增强项目扫描
就是本次启用，不要求改变该开关，但会沿用这里的 CLI 路径、模型和推理强度。
CLI 登录成功后，模型下拉框会直接读取当前 CLI 返回的
可见模型列表，避免固定列表过期；目录读取失败时仍保留默认模型和当前配置。留空 CLI 路径时，应用会自动跳过不可执行的 WindowsApps
候选，并使用 PATH 或当前用户 npm 目录中真正可运行的独立 CLI。应用不绑定具体 CLI
版本，而是检查复核所需能力；从浏览器授权返回应用时会自动刷新登录和兼容状态。

应用启动 CLI、GitHub CLI 或 Windows 计划任务工具时使用隐藏窗口模式，后台检查不会再
弹出控制台黑框。

耗时操作会在页面顶部显示“正在处理”、完成或失败状态；对应按钮在运行期间会显示
旋转图标和当前动作，避免重复点击。
