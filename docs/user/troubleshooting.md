# 故障排查

先做三件事：使用最新发布包，运行 `csm doctor`，并保留错误文字、事务 ID
和最新日志。每个来源都会先通过必选的本地分层评估；增强项目扫描是可选的，
失败时仍可切回标准安装。

## 启动后窗口全白

确认已安装 WebView2 Runtime，并运行 `csm doctor`。如果仍无法加载，请保留
提示文字和 `data/logs` 下最新日志用于诊断。

## GUI 无法启动

- 确认 Windows 10/11 已安装 WebView2 Runtime；
- 运行 `csm doctor`；
- 检查自定义数据目录的写入权限。

## 私有仓库 401/404

- 运行 `gh auth status`；
- 检查 Token 是否有仓库 Contents 读取权限；
- 私有仓库无权限时 GitHub 可能返回 404。

## 安装窗口显示 GitHub 403

403 通常表示凭据未通过验证或当前 GitHub API 额度已用尽。安装窗口会保留输入，
并在原位置显示错误、技术详情、重试入口和“检查 GitHub 凭据”：

1. 打开“设置 → GitHub 凭据与限额”，验证当前凭据；
2. 如果显示限流，等到提示的恢复时间再重试；
3. 私有仓库应确认凭据具有该仓库的 Contents 读取权限；
4. 不要反复提交同一个请求；也可以先使用已经下载好的本地目录。

错误不需要通过关闭安装窗口才能看到。若窗口中没有错误卡片，请保留安装窗口中的
输入和技术详情，并改用已经下载好的本地目录重试。

## 增强项目扫描不可用

- 必选的本地评估仍可单独完成；增强项目扫描失败不会阻止标准安装；
- 在“设置”中检查 Codex CLI、登录状态和可用模型；
- 确认账户有可用额度；点击“运行增强项目扫描”就是本次启用，不要求打开
  安全中心的复核总开关；
- 对私有仓库确认允许 Codex CLI 处理完整仓库上下文；
- 计划需要 MCP 时，选择真实的 Git 或 SVN 项目目录，不能使用暂存目录或符号链接；
- 增强项目扫描失败时可以重试一次，或保留来源分析并切换到标准安装。
- 如果提示多个不同 Skill 使用同一名称，优先点击“使用建议的 Codex 目录”；
  没有建议时，根据技术详情中的冲突路径输入具体仓库子目录。
- 如果仍只显示 `exit status 1`，保留安装窗口中的实际错误和技术详情。

## 计划安装执行中断

先查看安装窗口的步骤时间线和恢复建议。失败或取消会先自动恢复已完成的可逆
步骤；恢复状态为“已完成”后可以重试计划。如果恢复不完整，先使用窗口或历史页
中的“回滚”继续恢复。应用会按事务记录处理 Skills、受管工具和由它写入的 MCP
配置。成功的计划安装也可以主动回滚。

如果 Codex 配置或托管文件在安装后被其他程序修改，自动回滚会拒绝覆盖这些修改。
此时不要直接删除目录；保留事务 ID 和技术详情，按照界面给出的备份、隔离区和
人工恢复路径处理。标为“手动”的步骤从未由应用执行，也不属于自动回滚范围。

## Skill 无法更新

- 检查是否存在本地修改；
- 检查来源锁中的仓库、路径和 ref；
- 重新生成计划，不要复用过期 plan ID。

## 更新失败

查看报告和事务 ID，再运行：

```powershell
csm rollback --transaction <ID>
```
