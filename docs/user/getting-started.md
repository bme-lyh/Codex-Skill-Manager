# 入门

## 启动发布版

1. 下载并解压 Windows 发布包。
2. 将 `CodexSkillManager.exe` 和 `csm.exe` 保存在同一目录。
3. 双击运行 `CodexSkillManager.exe`。
4. 默认 Skills 根目录为 `%USERPROFILE%\.codex\skills`。

便携版包含 `portable.marker`，配置和运行状态保存在发布目录；标准版把应用状态
保存在 `%USERPROFILE%\.codex\skill-manager`。数据、日志、报告、备份、隔离区和
暂存区可以在 **设置** 中分别改为绝对路径，修改路径后请重启应用。

首次运行默认显示简体中文。如需 English，打开 **设置 → 语言** 并选择 **English**；
界面会立即切换并自动保存。

当前桌面端有五项一级导航：**首页、资产、安全、活动、设置**。资产包含 **Skills**
和 **分组**，活动包含 **更新**、**历史与回滚**、**隔离区** 和 **报告**。

## 四步添加项目

从顶部打开 **添加项目**。GitHub 链接和本地目录都经过同一条流程：

1. **来源**：输入仓库、目录或直接的 `SKILL.md` 链接。GitHub 来源固定到完整
   Commit；本地来源复制到有边界、由应用管理的快照。
2. **理解与计划**：应用读取项目说明和标记，判断项目类型，发现 Codex Skills，
   并检查实际目标。检查按必选、条件触发和可选分组；本地阶段不会调用 Codex、
   下载依赖或执行仓库脚本。
3. **检查与确认**：查看证据、选中的 Skills、具体写入目标、风险、权限和恢复方式。
   四种结论是 **可安装**、**需要确认**、**已阻止**、**检查未完成**，只有前两种可以继续。
4. **安装与结果**：批准目标或结构化步骤后，窗口显示进度，记录事务，重新读取最新
   Skills 和操作状态，并保留恢复状态。

入口不会要求用户选择安装模式。复杂项目可在 **更多选项** 中点击
**运行增强项目扫描**。Codex 是可选的语义检查提供器，不是独立安装模式；扫描阶段
只读、关闭 Shell，并且需要本地验证和明确授权。**切换标准安装**也位于 **更多选项**，
它只写入选中的 Skill 目录，不配置 MCP 或额外依赖。

评估会自动理解项目并运行本地分层检查。来源过期、被替换、摘要不一致、未知、
不支持或大小写变体的 `.system` 目标都会安全停止，并要求重新检查。`.system` 始终只读；
没有 Codex Skill 的普通项目不会被复制到全局 Skills 目录；MCP 所需的项目目录必须
由用户明确选择。

默认 Skills 根目录为 `%USERPROFILE%\.codex\skills`。安装完成后，窗口会刷新 Skills
列表和操作状态；如果刷新失败，已完成结果仍会保留，应重试刷新而不是重复安装。请在
**历史与回滚** 中查看事务和回滚入口，在 **隔离区** 中恢复已移除的 Skills。

## 添加随包提供的 Codex Skill

发布包包含 `agent-skill\codex-skill-manager`。如需把它加入全局 Codex Skills，打开
**添加项目**，选择 **本地目录**，选中发布包内的 `agent-skill`，按四步流程检查并安装
选中的 Skill。源码检出目录对应 `skills\codex-skill-manager`。

## 管理已有 Skills

打开 **资产 → Skills**，选择未管理项目并点击 **管理**。只读预览会显示识别到的仓库、
来源路径、建议分组、置信度和扫描结果。确认后只记录来源和哈希，不移动或改写 Skill
内容。无法确认远程来源时，会建立独立的本地分组。

## 可选的增强项目扫描

**运行增强项目扫描**适用于还需要 Python 工具或 Codex MCP 的复杂仓库。使用前在
**设置**中检查 Codex CLI，确认它已安装、已登录且有可用额度。应用会在关闭 Shell 的
情况下处理准备好的来源，返回项目概述、安全结论、证据限制、声明式安装方式、结构化
步骤和权限清单。

自动执行仅限于安装选中的 Skills、从官方 PyPI 安装经过核验的固定版本 Python 工具，
以及写入应用管理的 Codex MCP 配置。仓库脚本、自由格式命令、不安全或不支持的工作
都会保留为人工步骤。受管 Python 工具和 MCP 自动集成需要 GitHub 来源以核对包归属；
MCP 必须使用真实 Git 或 SVN 项目目录。部分完成时，已完成的自动步骤和剩余人工工作
都会写入结果。

只读扫描不会下载依赖。只有在用户批准生成计划后，应用才会从官方 PyPI 下载完整
Wheel 依赖到隔离暂存区，并锁定文件名和 SHA256；分析阶段不会安装或运行它们。源码包
会被拒绝，含本机代码的 Wheel 需要单独的 High 风险批准。私有仓库使用者在启用前应
确认来源上下文、数据和额度要求。

来源解析、GitHub 403、Codex 和执行错误会直接显示在 **添加项目** 窗口中；限流会显示
恢复倒计时。可以重试或取消，长任务可隐藏到后台，重新打开会恢复进度。失败或取消时，
应用按逆序恢复已完成的可逆步骤；失败重试会恢复精确的 Skill 子集、权限和项目目录，
需要重新检查后才能继续。

CLI 保留脚本工作流所需的底层兼容契约，详见 [CLI 参考](cli-reference.md#计划安装)。

## 检查更新

打开 **活动 → 更新**，点击 **检查更新**。该操作只比较 Commit。选择一个或多个可更新
来源，查看不可变 Commit、实际目标、风险结果和 Skill 选择，再应用更新。每个来源都有
独立的事务、备份和回滚入口。

定时检查不会自动安装更新。
