# 安全扫描

本地扫描覆盖：

- 提示注入和优先级覆盖；
- Cookie、Token、私钥和凭据访问；
- 动态命令执行；
- 下载后执行；
- 递归或批量删除；
- 计划任务和持久化；
- 新增外部 URL；
- Base64 等混淆载荷；
- Codex 配置和全局规则修改；
- 符号链接、路径逃逸、大文件和未批准类型。

风险处理：

| 级别 | 默认行为 |
|---|---|
| Informational / Low | 记录 |
| Medium | 显示并审查 |
| High | 默认阻止写入；人工忽略后可继续 |
| Critical | 默认阻止写入；人工忽略后可继续 |

扫描不执行 Skill 脚本，也不上传内容。

安装和更新计划只扫描实际可选择、会被写入的 Skill 目录。仓库根目录中的项目首页、
开发工具、CI 工作流或测试并非安装目标，因此不会用来阻止无关 Skill；如果同样的
风险内容位于目标 Skill 内，High/Critical 门禁仍然生效。门禁只依据尚未忽略的
有效风险簇：仍有 High 或 Critical 时禁止写入；人工忽略后，该风险簇不再参与门禁。

如果仓库在不同目录中放置了内容完全相同的同名 Skill（例如同时提供普通安装路径和
插件打包路径），应用会自动去重并选择较短、较规范的路径。若同名 Skill 的实际内容
不同，应用会停止并要求使用者指定明确路径，避免静默安装错误版本。

文件数量限制按本次选中 Skills 的实际总文件数计算。超过上限时，错误信息会同时显示
实际总数和配置上限；使用者应先指定更小的 Skill 路径，或在审查仓库规模后调整
`scanner.maxFiles`，不应仅为绕过检查而放宽限制。

安全中心按“分组 → Skill → 警告”展示结果和数量。每个 Skill 内部仍会把同类命中合并，
避免逐条处理重复提示。完整原始发现始终写入本地报告文件。

安全中心会保存每个 Skill 检查时的内容指纹。已检查且内容没有变化的 Skill 默认不进入
下一次检查队列；尚未检查或内容已经变化的 Skill 默认选中。使用者可以通过复选框、全选、
反选、清空或“恢复推荐”随时改变本次队列。通过应用安装、更新或管理且检查成功的 Skill
也会记录为已检查。

## 计数与忽略

导航栏红点只统计每个扫描目标最新报告中、尚未忽略的唯一 High/Critical 风险簇。
发现通过规则、规范化文件路径和命中内容生成稳定指纹；重复扫描不会重复增加数量。

使用者可以在安装、更新、安全中心和已有 Skills 管理窗口中一键忽略单个风险簇，
也可以一次忽略当前报告的全部待处理风险簇。所有级别和确定性规则使用同一操作，
无需先运行 Codex，也不强制填写原因。决定会应用到簇内全部稳定指纹，并以单个原子事务
写入日志。安装应用前，后端会重新读取最新忽略记录，而不是信任界面传入的风险状态。
恢复警告后，该发现会重新计入风险并重新参与门禁。

图形界面先显示本次检查的分组数、Skill 数、待处理数和已忽略数，再在各 Skill 下展示
等级、原因、代表性证据和处理状态。

## 本地安全底线与人工权限

符号链接逃逸、危险可执行文件、路径穿越和明确的递归/批量删除属于确定性规则，默认
阻止安装。Codex 结论仅供参考，不能替使用者作出决定。使用者拥有最高决定权，可以像
其他风险一样直接忽略单簇或一键忽略全部；原因可选，操作目标、时间和事务类型仍会记录。

## 可选 Codex 辅助复核

设置中可启用独立 Codex CLI 作为第二阶段语义复核。默认关闭，默认使用 Codex 当前默认
先进模型和中等推理强度。CLI 登录成功后，模型选项会从当前 CLI 的公开模型目录动态载入，
不会绑定某个固定模型或版本。应用把被审查仓库或目标目录设为 Codex 的只读工作目录，
先识别其中有效的 Skills，再按应用分组复核。同一分组内的 Skills 始终放在同一个任务中，
以保留共享文件和相互引用的上下文。每个 Skill 都会独立输出摘要、结论、置信度、
关注项、证据文件和关联风险簇，避免多 Skill 仓库被压缩成一段混合说明。

默认同时运行 2 个分组，可在设置页调整。安装和更新时，只复核界面中当前选中的 Skills。
较高并行度通常更快，但也更可能触发模型服务限流。界面会实时显示准备、排队、运行、
部分完成或完成状态，以及当前分组、Skill、完成数量、Codex 分析活动数和耗时。单个分组
失败时，其他分组仍会继续，
已完成的 Skill 结论会保留在报告中。即使本地规则没有命中警告，也可以主动运行 Codex
完整上下文复核；此时每个 Skill 仍会获得独立结论。

每个分组任务可访问完整仓库上下文，并按需读取相关文件；版本控制元数据、生成目录和
依赖目录不参与上下文盘点。本地规则只传递规则、等级、风险簇 ID、命中数和文件数等概览，
不重复传递证据正文或文件路径。它只是补充线索，不是 Codex 的结论。复核使用临时会话、只读沙箱、禁止审批和
结构化输出，不执行仓库代码、不访问网络、不修改文件。

启用前必须安装并登录 Codex CLI。Codex 复核会消耗账户额度，耗时和用量取决于 Skill
数量、文件大小、模型及推理强度；不启用时不影响本地检查和其他管理功能。

查看完整复核结果后，可以选择“一键采纳建议”。该操作只选取 Codex 判定为误报、
文档/示例，或因本地底线被标记为“必须人工决定”的风险簇；真实风险、上下文不足等结论
保持待处理。使用者也可以不采纳 Codex 建议，直接使用独立的“一键忽略全部警告”。
Codex 建议和普通人工忽略均不要求确定性规则二次确认，恢复入口仍按风险簇保留。

必须先让独立 Codex CLI 完成 `codex login`。应用会逐一验证 PATH 和当前用户 npm 目录中的
候选，自动跳过无法由第三方进程启动的 WindowsApps 内置版本；也可以在设置页手动指定
独立 `codex.exe` 或 `codex.cmd` 的绝对路径。兼容性按 `exec`、只读沙箱、审批策略和
结构化输出等实际能力判断，不锁定版本号。
