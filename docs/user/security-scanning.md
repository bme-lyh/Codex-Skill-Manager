# 安全扫描

每个来源都会先完成必选的本地分层评估，再决定是否需要可选的 Codex 增强分析。
本地扫描不执行 Skill，也不上传内容；Codex 分析在单独同意前只读。请记住三条底线：
Critical 不可忽略，High 必须逐簇确认并填写非空原因，报告级批量忽略只处理已知的
Medium 及以下风险。

本地扫描覆盖：

- 提示注入和优先级覆盖；
- Cookie、Token、私钥和凭据访问；
- 动态命令执行；
- 下载后执行；
- 递归或批量删除；
- 计划任务和持久化；
- 新增外部 URL；
- Base64 等混淆载荷；
- Codex 配置和全局规则修改；
- 符号链接、路径逃逸、大文件和未批准类型。

风险处理：

| 级别 | 默认行为 |
|---|---|
| Informational / Low | 记录 |
| Medium | 显示并审查 |
| High | 默认阻止写入；必须逐簇确认并填写原因后才可接受 |
| Critical | 始终阻止写入，不可忽略 |

扫描不执行 Skill 脚本，也不上传内容。

安装和更新计划只扫描实际可选择、会被写入的 Skill 目录。仓库根目录中的项目首页、
开发工具、CI 工作流或测试并非安装目标，因此不会用来阻止无关 Skill；如果同样的
风险内容位于目标 Skill 内，High/Critical 门禁仍然生效。门禁只依据尚未忽略的
有效风险簇：仍有 High 或 Critical 时禁止写入；只有 High 可以通过逐簇确认和非空原因
转为已接受，Critical 始终参与门禁。

如果仓库在不同目录中放置了内容完全相同的同名 Skill（例如同时提供普通安装路径和
插件打包路径），应用会自动去重并选择较短、较规范的路径。若同名 Skill 的实际内容
不同，应用会停止并要求使用者指定明确路径，避免静默安装错误版本。

文件数量限制按本次选中 Skills 的实际总文件数计算。超过上限时，错误信息会同时显示
实际总数和配置上限；使用者应先指定更小的 Skill 路径，或在审查仓库规模后调整
`scanner.maxFiles`，不应仅为绕过检查而放宽限制。本地来源创建不可变快照时，同一上限
还会统计目录项，防止仅用超大目录树绕过资源边界。

安全中心按“分组 → Skill → 警告”展示结果和数量。每个 Skill 内部仍会把同类命中合并，
避免逐条处理重复提示。完整原始发现始终写入本地报告文件。

安全中心会保存每个 Skill 检查时的内容指纹。已检查且内容没有变化的 Skill 默认不进入
下一次检查队列；尚未检查或内容已经变化的 Skill 默认选中。使用者可以通过复选框、全选、
反选、清空或“恢复推荐”随时改变本次队列。通过应用安装、更新或管理且检查成功的 Skill
也会记录为已检查。

## 计数与忽略

导航栏红点只统计每个扫描目标最新报告中、尚未忽略的唯一 High/Critical 风险簇。
发现通过规则、规范化文件路径和命中内容生成稳定指纹；重复扫描不会重复增加数量。

使用者可以在安装、更新、安全中心和已有 Skills 管理窗口中处理风险簇。Medium 及以下
可使用普通忽略；High 必须逐簇明确确认并填写非空原因；Critical 不可忽略。批量操作
不会接受 High 或 Critical。决定会应用到簇内全部稳定指纹，并以单个原子事务
写入日志。安装应用前，后端会重新读取最新忽略记录，而不是信任界面传入的风险状态。
恢复警告后，该发现会重新计入风险并重新参与门禁。

图形界面先显示本次检查的分组数、Skill 数、待处理数和已忽略数，再在各 Skill 下展示
等级、原因、代表性证据和处理状态。

## 本地安全底线与人工权限

符号链接逃逸、危险可执行文件、路径穿越和明确的递归/批量删除属于确定性底线，默认
阻止安装。Codex 结论仅供参考，不能替使用者解除底线。Critical 永远不能忽略；High
只能经逐簇确认和原因记录后接受，操作目标、时间和事务类型均会记录。

## 可选 Codex 风险复核

设置中可启用独立 Codex CLI 作为第二阶段语义复核。默认关闭，默认使用 Codex 当前默认
先进模型和中等推理强度。CLI 登录成功后，模型选项会从当前 CLI 的公开模型目录动态载入，
不会绑定某个固定模型或版本。应用先识别有效 Skills，再按应用分组打包完整上下文，
关闭 Codex Shell 工具，并使用只含应用输出的临时工作目录。同一分组内的 Skills 始终放在同一个任务中，
以保留共享文件和相互引用的上下文。每个 Skill 都会独立输出摘要、结论、置信度、
关注项、证据文件和关联风险簇，避免多 Skill 仓库被压缩成一段混合说明。

默认串行运行分组，可在设置页调整。安装和更新时，只复核界面中当前选中的 Skills。
较高并行度通常更快，但也更可能造成 Codex CLI 模型刷新竞争或服务限流。界面会显示
准备、排队、运行、重试、部分完成或完成状态，以及当前分组、Skill、完成数量、Codex
分析活动数和耗时。切换页面不会中断任务或丢失结果，迟到的旧进度事件也不会覆盖较新的
计数。单个分组首次失败或结构化结果遗漏 Skill 时会串行重试一次；重试仍失败时，其他
分组已完成的 Skill 结论会保留在报告中。即使本地规则没有命中警告，也可以主动运行完整
上下文复核；每个 Skill 仍会获得独立结论。

每个分组任务会收到完整打包上下文：UTF-8 文本包含原文，二进制文件使用路径、大小和
SHA-256 表示；只有来源根目录中确认为真实元数据的 `.git`、`.hg`、`.svn` 会跳过。
普通同名目录以及 `.csm-backups`、`.csm-quarantine` 也会检查，不能用来隐藏内容。
大来源会按稳定文件边界分块，每个文本文件只进入一块，再统一汇总。本地规则只传递
规则、等级、风险簇 ID、命中数和文件数等概览，不重复传递证据正文。它只是补充线索，
不是 Codex 的结论。复核使用临时会话、关闭 Shell、禁止审批和结构化输出；除 Codex
服务本身的通信外，不允许仓库内容触发网络请求，也不执行仓库代码、不修改文件或读取
打包内容以外的主机文件。明确选择本地来源时，不要选择含有无关备份或私有资料的宽泛
父目录。

启用前必须安装并登录 Codex CLI。Codex 复核会消耗账户额度，耗时和用量取决于 Skill
数量、文件大小、模型及推理强度；不启用时不影响必选本地评估和其他管理功能。

查看完整复核结果后，可以选择“一键采纳建议”。该操作只选取 Codex 判定为误报、
文档/示例，或因本地底线被标记为“必须人工决定”的风险簇；真实风险、上下文不足等结论
保持待处理。使用者也可以不采纳 Codex 建议，只批量忽略 Medium 及以下可处理项；
High 必须逐簇确认，Critical 不可忽略。
Codex 建议不能解除 Critical，也不能代替 High 的明确确认与原因；恢复入口仍按风险簇保留。

## 安装前分层评估

所有来源（不论是否使用 Codex）都先完成持久化本地评估：固定 GitHub Commit 或创建
本地受管快照，阅读项目说明和安装线索，分类项目，发现 Codex Skills，扫描真实目标，
并把检查分为必选、按条件触发和可选。评估输出“可继续、需关注、已阻止、检查不完整”
四种门禁状态。执行前后端会从绑定的来源重新计算评估；来源变化、过期、未知状态、
摘要不一致、不支持目标和大小写变体 `.system` 均失败关闭。

必须先让独立 Codex CLI 完成 `codex login`。应用会逐一验证 PATH 和当前用户 npm 目录中的
候选，自动跳过无法由第三方进程启动的 WindowsApps 内置版本；也可以在设置页手动指定
独立 `codex.exe` 或 `codex.cmd` 的绝对路径。兼容性按 `exec`、关闭 Shell、审批策略和
结构化输出等实际能力判断，不锁定版本号。

## Codex 增强分析与辅助安装的权限边界

“增强项目扫描”和上面的风险复核使用同一个可选 CLI，但用途不同：风险复核只
给出安全建议；辅助安装先对固定 Commit 的 GitHub 暂存仓库或明确的本地来源执行
可复用项目扫描，输出项目概述、安全结论和安装方式。安全扫描可以复用其中的安全
结果，而不要求生成安装计划。安全中心的风险复核由设置中的总开关控制；在安装窗口
选择 Codex 增强分析，或在 CLI 使用 `--assist`，就是对本次辅助安装的明确启用。两者
都会消耗 Codex 额度。

项目扫描不是安装授权。只有使用者阅读结果并明确同意后，Codex 才能生成计划。
对于 Skill 功能必需的敏感能力，结论可以标为“具有上下文风险/需要提示”，而不应
仅因能力敏感就判定为恶意。Codex 生成的计划也不是执行权限。应用会在本地重新验证来源、计划摘要和配置指纹，
把未知动作降级为人工步骤，并根据允许的动作自动生成权限清单。只有使用者明确
批准后，以下类型才能执行：

- 安装本次扫描并选中的 Skills；
- 使用分析阶段从官方 PyPI 锁定的完整 Wheel 依赖安装 Python 工具；
- 把该受管工具以固定 `serve` 参数写入 Codex MCP 配置。

只读项目扫描不会访问 PyPI。使用者同意生成计划后，如果识别到受支持的 Python
工具，应用才可能访问官方 PyPI，把完整依赖下载到
隔离暂存区。它会记录每个包的名称、版本、文件名和 SHA256，此时不会安装或运行
任何包。源码包、直接下载链接和不兼容文件会被拒绝；含本机代码的 Wheel 会标为
高风险，并要求单独批准。下载时，应用会让 pip 只通过临时本地代理访问 PyPI 的
两个官方域名，并逐个核对 PyPI 元数据中的文件名、地址和哈希。正式执行只接受
清单中的文件和哈希，使用离线安装。这个限制不是 Windows 网络沙箱，因此仍应
使用可信的本机 Python 和 pip。

应用不运行仓库脚本，不执行任意 Shell 命令，不接受 Codex 指定环境变量或任意
写入路径，也不静默覆盖已有 MCP。Python 下载、受管工具写入、工具启动和 MCP
配置分别需要明确权限；MCP 还必须绑定到使用者指定的真实版本控制项目目录。
受管工具与 MCP 自动集成还要求 GitHub 来源，以便通过官方 PyPI 元数据核对包
归属。无法满足这些条件的复杂步骤仍会显示在计划中，但只能人工完成。已批准的
安全步骤可以先执行，最终状态会明确显示“部分完成”和剩余人工事项。

自动步骤使用事务、备份、输出哈希和隔离区。失败会尝试逆序恢复；如果目标在安装
后被修改，恢复会停止而不是覆盖新内容，并给出明确的人工处理路径。
